# Stable Update Channel

VeloFile V1 release builds are distributed as signed MSIX packages from the project GitHub Releases page. The MSIX installs side by side with Windows File Explorer and does not register VeloFile as an Explorer replacement.

## Published Release Source

The published release source is a signed Git tag in this repository, plus the GitHub Release created from that tag. Release artifacts must be traceable to the tag, the CI run, and the package metadata generated by `scripts/package-msix.ps1`.

## Signing Identity

The release signing identity is the MSIX certificate subject `CN=VeloFile Open Source`. Contributor local packaging uses unsigned local packaging metadata only; signed release packaging requires a release-owner certificate thumbprint supplied to `scripts/package-msix.ps1`.

## Versioning Policy

MSIX package versions use four numeric parts: `major.minor.patch.revision`. V1 preview packages start at `0.1.0.0`. Stable V1 packages must monotonically increase the package version and match the release tag policy documented in the release notes.

## Update Cadence

The stable update cadence is conservative: security and data-loss fixes can ship out of band, while normal feature and compatibility updates should batch behind release verification. A release owner records the cadence decision in the GitHub Release notes.

## Rollback

Rollback is uninstalling the MSIX package and installing an earlier signed release if needed. VeloFile does not own global Explorer replacement behavior or system file associations, so rollback does not require repairing Explorer or default app registrations.
